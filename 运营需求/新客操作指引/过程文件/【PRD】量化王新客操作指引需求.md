## 术语定义

| 术语 | 定义 |
|------|------|
| 新客（新设备） | 首次安装/使用 APP 的设备，以 device_id 为判断依据，未完成过新手引导流程 |
| device_id | APP 启动时生成的设备唯一标识，用于在用户未登录状态下识别设备身份 |
| 核心操作路径 | 新客需完成的标准化操作流程：创建策略 → 选择股票择时 → 登录/注册 → 回测 → 保存策略（了解实盘入口）→ 大神策略 → 广场社群 |
| 引导浮层 | 覆盖在 APP 页面上的半透明蒙版引导提示层，用于高亮标注点击位置、说明操作目的 |
| 默认策略 | 后端预配置的新手引导专用策略模板，用户在登录后进入策略编辑页时自动加载，无需手动配置参数 |

## 一、需求背景与目的

### 1.1 业务背景

1. 当前量化王 APP 新用户注册后流失严重，核心功能（策略创建、回测、大神策略、社群）的使用率偏低
2. **更关键的问题是：大量新用户在注册/登录之前就已流失**，根本走不到策略创建环节
3. 现有流程中，用户在首页点击「创建策略」后才要求登录，缺乏前置引导，用户不知道该做什么
4. 需要将新手引导前置到未登录状态，在用户打开 APP 的第一时间就进行引导，降低使用门槛

### 1.2 需求目标

| 目标 | 说明 |
|------|------|
| 降低新客流失 | 将引导前置到 APP 启动时（无需登录），在用户打开 APP 的第一时间引导其体验核心功能 |
| 提升注册转化率 | 通过引导流程自然引入登录/注册环节，让用户在有明确操作目标的情况下完成注册，而非冷启动注册 |
| 提升核心功能使用率 | 引导新客按指定路径依次体验：创建策略 → 回测 → 保存策略（了解实盘入口）→ 大神策略 → 广场社群 |
| 建立数据度量体系 | 通过全链路埋点，量化各步骤的完成率与跳出率，为后续引导优化提供数据支撑 |
| 提升新客转化效率 | 结合新手礼包激励（基于 device_id 判断，防止薅羊毛），推动新客从"新设备用户"向"活跃用户"转化 |

### 1.3 适用范围

- **适用对象**：首次使用 APP 的新设备（以 device_id 判断）
- **覆盖范围**：从 APP 启动到完成首次核心操作的全流程，包含引导交互（含登录/注册环节）、文案、埋点、状态管理等全环节
- **不适用**：已完成过引导或已跳过引导的设备（device_id 已有引导记录）不触发引导

## 二、需求清单

| 功能模块 | 详细说明 | 涉及角色 |
|---------|---------|---------|
| 新手引导流程（前端） | 新设备首次打开 APP 后触发 5 步引导流程，采用浮层高亮 + 文案提示的交互形式，支持跳过与中断恢复 | 前端开发 |
| 引导启动与跳过 | APP 启动时根据 device_id 判断新设备，直接在首页展示蒙版高亮「创建策略」按钮开始引导，每步引导气泡提供「X 关闭」和「跳过引导」文本两个跳过入口 | 前端开发 |
| 第一步：创建策略 | 引导点击「创建策略」→ 选择「股票择时」→ 触发登录/注册 → 登录后进入策略编辑页（加载默认策略）→ 回测 | 前端开发、后端开发 |
| 第二步：保存策略 | 回测完成后引导用户点击「仅保存」，保存策略 | 前端开发 |
| 第三步：我的策略（了解实盘入口） | 跳转至首页，引导用户进入「我的策略」页面，告知实盘交易入口位置 | 前端开发 |
| 第四步：查看大神策略 | 引导跳转至大神策略页面-官方策略，浏览优质策略内容 | 前端开发 |
| 第五步：广场社群互动 | 引导跳转至广场页面，鼓励用户浏览社群内容并互动 | 前端开发 |
| 引导完成与礼包（预留） | 新设备在引导结束或跳过后，满足条件时触发新手礼包弹窗（当前仅预留入口，暂不实际弹出） | 前端开发 |
| UI / 视觉规范 | 浮层蒙版样式、IP 形象（小牛）、按钮样式、引导动画等视觉规范 | UI 设计、前端开发 |
| 引导状态管理（前端 + 后端） | 登录前：前端本地存储引导状态（基于 device_id）；登录后：同步至后端，关联 device_id + user_id | 前端开发、后端开发 |
| 默认策略配置（后端） | 为新手引导预配置默认策略模板，供第一步回测使用 | 后端开发 |
| 登录流程适配（前端） | 引导过程中触发登录时，登录成功后不返回原页面，而是直接进入策略编辑页面继续引导 | 前端开发 |
| 新手礼包逻辑（后端，预留） | 基于 device_id 判断礼包领取资格（防薅羊毛），当前仅预留接口，暂不上线 | 后端开发 |
| 数据表设计（后端） | 新增设备引导状态表、引导事件明细表 | 后端开发 |
| 接口设计（后端） | 引导状态同步、步骤完成上报、礼包领取等接口 | 后端开发 |
| 数据埋点 | 全链路埋点：每步的进入、完成、跳出事件，用于统计各步骤转化率 | 前端开发、数据 |


## 三、前端需求详情 — 引导流程总览

### 3.1 整体流程链路

```
APP 启动（获取 device_id）
  │
  ▼
判断 device_id 是否为新设备
（优先查本地存储，无记录则为新设备）
  │
  ├── 非新设备 → 正常进入 APP 首页
  │
  ▼ 新设备
┌──────────────────────────────────────────────┐
│  直接在首页展示引导蒙版                           │
│  高亮「创建策略」按钮，开始第一步引导               │
│  （气泡含「X 关闭」+ 「跳过引导」文本入口）         │
└──────────────────┬───────────────────────────┘
                   │
                   ├── 用户点击「X」或「跳过引导」
                   │   → 关闭蒙版，进入 APP 首页
                   │   （本地记录 skipped，触发新手礼包判断）
                   │
                   ▼ 用户点击高亮按钮
┌──────────────────────────────────────────────┐
│  第一步：创建策略（含登录环节）                     │
│  ① 首页引导点击「创建策略」                        │
│  ② 引导选择「股票择时」                           │
│  ③ 点击时校验登录状态 → 未登录跳转登录页            │
│  ④ 登录/注册成功 → 直接进入策略编辑页（非返回原页面） │
│  ⑤ 自动加载默认策略 → 引导点击「回测」              │
│  ⑥ 等待回测结果                                  │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  第二步：保存策略                                │
│  回测结果页 → 引导点击「仅保存」                   │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  第三步：我的策略（了解实盘入口）                   │
│  跳转首页 → 引导进入「我的策略」→ 告知实盘入口      │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  第四步：查看大神策略                             │
│  引导点击「查看大神策略」→ 跳转大神策略页面          │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  第五步：广场社群互动                             │
│  跳转至广场页面，浏览社群内容                      │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│  引导完成                                       │
│  标记引导完成（本地 + 后端同步）                    │
│  触发新手礼包判断（预留，暂不弹出）                 │
└──────────────────────────────────────────────┘
```

> **跳出说明：**
> - 每个引导步骤的气泡上均提供两个跳过入口：「X 关闭」按钮和「跳过引导」文本链接，效果相同。
> - 用户点击「X 关闭」、「跳过引导」文本、Android 系统返回键、iOS 侧滑返回，均视为**主动跳过引导**，引导状态标记为 `skipped`，后续不再触发引导。
> - 仅 APP 闪退、杀进程、页面 unload 等**非主动退出**才视为中断，引导状态保持 `in_progress`，24 小时内再次打开 APP 可恢复进度。

### 3.2 触发条件

| 条件项 | 规则说明 |
|--------|---------|
| 触发对象 | 新设备（device_id 在本地无引导记录） |
| 触发时机 | APP 启动时，获取 device_id 后立即判断，**无需登录** |
| 判断依据 | 前端本地存储中查询该 device_id 的引导状态，无记录则视为新设备 |
| 老设备处理 | 本地已有引导记录（`completed` 或 `skipped`）的设备，不再触发引导 |

### 3.3 生命周期规则

| 场景 | 处理规则 |
|------|---------|
| 新设备首次打开 APP | 直接在首页展示引导蒙版，高亮「创建策略」按钮，本地记录引导状态为 `in_progress`，当前步骤为 `step_1` |
| 用户点击「X 关闭」或「跳过引导」文本（任意步骤） | 关闭引导蒙版，进入 APP 正常页面，本地记录引导状态为 `skipped`，不再触发引导 |
| 用户在引导过程中点击 Android 返回键 / iOS 侧滑返回 | **等同于跳过引导**，本地记录引导状态为 `skipped`，不再触发引导 |
| 用户在引导过程中非主动退出（APP 闪退/杀进程/页面 unload） | 引导暂停，本地记录当前步骤编号，状态保持 `in_progress` |
| 用户在引导过程中完成登录/注册 | 登录成功后，将本地引导状态同步至后端（关联 device_id + user_id），后续状态变更同时更新本地和后端 |
| 用户完成全部 5 步 | 引导状态标记为 `completed`（本地 + 后端同步） |
| 引导完成 / 跳过后再次打开 APP | 不再触发引导 |

### 3.4 引导状态存储机制

引导状态分两阶段存储：

| 阶段 | 存储位置 | 标识键 | 说明 |
|------|---------|--------|------|
| 登录前 | 前端本地存储（LocalStorage / SharedPreferences） | device_id | 用户未登录时，引导状态仅存本地，以 device_id 为 key |
| 登录后 | 前端本地 + 后端数据库 | device_id + user_id | 登录成功后，将本地状态同步至后端，后续状态变更双写（本地 + 后端） |

**同步规则：**

| 场景 | 处理方式 |
|------|---------|
| 用户在引导过程中完成登录 | 登录成功后立即调用后端接口，将当前引导状态（含 device_id、guide_status、current_step）同步至后端 |
| 本地有引导记录但后端无记录 | 以本地为准，同步至后端（首次登录场景） |
| 本地和后端都有记录且不一致 | 以本地为准（因为本地记录了最新的操作状态） |
| 用户卸载重装 APP | 本地记录丢失，但后端仍有 device_id 记录。若 device_id 不变，APP 启动时可调用后端接口查询（需登录态）；若 device_id 变化，视为新设备 |

### 3.5 中断恢复机制

仅针对**非主动退出**（APP 闪退/杀进程/页面 unload）场景，引导流程支持中断后恢复：

| 中断场景 | 恢复策略 |
|---------|---------|
| APP 被杀进程 / 闪退 | 下次打开 APP 时，读取本地存储的 `current_step`，直接跳转至对应页面继续引导，无过渡提示 |
| 中断记录有效期 | **24 小时内有效**。超过 24 小时未恢复，本地自动将引导状态更新为 `skipped`，不再触发引导 |
| 中断发生在登录前（step_1 的前半段） | 恢复时从中断的子步骤继续（如已点击创建策略但未登录，恢复后从策略选择页继续） |
| 中断发生在登录后（step_1 后半段及之后） | 恢复时从中断步骤继续，登录态仍有效则直接继续，登录态过期则需重新登录后继续 |
| 网络异常导致步骤上报失败 | 前端本地缓存当前步骤，网络恢复后补报；若本地与后端步骤不一致，以本地为准 |

### 3.6 各步骤跳出规则

| 操作 | 行为 | 埋点 |
|------|------|------|
| 点击浮层外区域 | 不响应，保持引导浮层展示（防误触） | — |
| 点击引导气泡上的「X 关闭」按钮 | **跳过引导**，关闭引导，进入 APP 正常页面，后续不再触发 | 记录 `guide_skip`，携带 `current_step`，`skip_reason = close_button` |
| 点击引导气泡上的「跳过引导」文本 | 同「X 关闭」行为 | 记录 `guide_skip`，携带 `current_step`，`skip_reason = skip_text` |
| 系统返回键（Android） | 同「X 关闭」行为 | 记录 `guide_skip`，`skip_reason = back_button` |
| 侧滑返回（iOS） | 同「X 关闭」行为 | 记录 `guide_skip`，`skip_reason = swipe_back` |



## 四、前端需求详情 — 各步骤交互说明

### 4.1 第一步：创建策略（含登录环节）

| 项目 | 说明 |
|------|------|
| 触发条件 | APP 启动时，根据 device_id 判断为新设备后，直接在首页展示引导蒙版，高亮「创建策略」按钮 |
| 目标页面 | 首页 → 策略选择页 → 登录页 → 策略编辑页 → 回测结果页 |
| 引导目标 | 引导用户完成 创建策略 → 选择股票择时 → 登录/注册 → 加载默认策略 → 回测 的完整子流程 |

**子步骤引导流程：**

本步骤包含多个子步骤，涉及页面跳转和登录环节：

| 子步骤 | 浮层高亮位置 | 引导文案 | 用户操作 | 是否需要登录 |
|--------|------------|---------|---------|------------|
| 1-1 | 首页「创建策略」按钮 | 点击这里，创建你的第一个策略 | 点击创建策略 | 否 |
| 1-2 | 策略选择页「股票择时」选项 | 选择「股票择时」开始体验 | 点击选择股票择时 | 否（点击后触发登录校验） |
| 1-3 | — （登录/注册页面） | — （正常登录/注册流程，无引导浮层） | 完成登录/注册 | **是（此步骤为登录环节）** |
| 1-4 | 策略编辑页（已自动加载默认策略） | 我们已经为你准备好了一个策略，直接回测看看效果吧 | 查看默认策略内容 | 是（已登录） |
| 1-5 | 「回测一下」按钮 | 最最最重要的是记得「回测一下哦～」 | 点击回测 | 是（已登录） |

**登录环节特殊处理：**

| 项目 | 说明 |
|------|------|
| 触发时机 | 用户在子步骤 1-2 点击「股票择时」时，前端校验登录状态，未登录则跳转登录页 |
| 登录页展示 | 正常的登录/注册页面，**不展示引导浮层**（登录流程不做引导干预） |
| 登录成功后跳转 | **不返回策略选择页（原逻辑）**，而是直接进入策略编辑页面，自动加载默认策略，继续引导流程 |
| 登录前引导状态保存 | 跳转登录页前，前端在本地记录当前引导进度（`current_step = step_1`，子步骤 = `1-3`） |
| 登录成功后状态同步 | 登录成功后，立即将本地引导状态同步至后端（关联 device_id + user_id） |
| 用户在登录页放弃登录 | 返回策略选择页，引导浮层恢复展示，继续高亮「股票择时」选项 |
| 用户在登录页关闭/返回 | 如果用户从登录页返回到策略选择页，引导继续；如果用户从策略选择页再返回到首页，视为跳过引导 |

**文案清单：**

| 元素 | 文案内容 |
|------|---------|
| 引导标题 | 第一步 创建策略 |
| 子步骤 1-1 文案 | 点击这里，创建你的第一个策略（小白也能使用的策略编辑器） |
| 子步骤 1-2 文案 | 选择「股票择时」开始体验 |
| 子步骤 1-4 文案 | 我们已经为你准备好了一个策略，直接回测看看效果吧 |
| 子步骤 1-5 文案 | 最最最重要的是记得「回测一下哦～」 |

**逻辑规则：**

| 场景 | 处理方式 | 埋点事件 |
|------|---------|---------|
| 用户完成回测（回测结果返回） | 自动进入第二步引导 | `guide_step1_complete` |

### 4.6 引导完成：新手礼包（预留）

| 项目 | 说明 |
|------|------|
| 触发条件 | 新设备（device_id）+ 引导已结束（完成或跳过）+ 该 device_id 未领取过新手礼包 |
| 当前状态 | **仅预留入口，暂不实际弹出**。待礼包内容确定后再开发上线 |

**触发逻辑：**

新手礼包基于 device_id 判断（防薅羊毛），与引导流程解耦，触发条件为：
1. 该 device_id 为新设备
2. 不需要弹出引导教程了（引导状态为 `completed` 或 `skipped`）
3. 该 device_id 尚未领取过新手礼包（`gift_claimed = false`）

满足以上三个条件时，触发新手礼包弹窗。即：
- 用户完成全部引导后 → 触发礼包
- 用户在引导过程中跳过引导后 → 触发礼包

> 注意：跳过引导时用户可能尚未登录，此时礼包状态仅记录在本地。用户后续登录后，礼包领取状态同步至后端。

**新手礼包规则：**

| 规则项 | 说明 |
|--------|------|
| 判断维度 | 以 device_id 为准（同一设备不同账号只能领一次，防薅羊毛） |
| 领取前提 | 新设备即可领取，不要求完成全部引导步骤 |
| 领取次数 | 每个 device_id 仅可领取一次 |
| 礼包内容 | 待运营确定，接口预留 `gift_info` 字段 |
| 当前阶段 | 仅预留前端入口和后端接口，暂不实际弹出和发放 |

## 六、后端需求详情 — 引导状态管理与接口设计

### 6.1 引导状态流转

引导状态分两阶段管理：登录前由前端本地存储管理，登录后同步至后端统一管理。

```
APP 启动（获取 device_id）
  │
  ▼
查询本地存储（device_id）
  │
  ├── 无记录 → 新设备，直接在首页展示引导蒙版
  ├── in_progress（24h内）→ 恢复引导
  ├── in_progress（超24h）→ 自动转 skipped
  ├── skipped → 不展示引导
  └── completed → 不展示引导
  
                    ┌──────────────┐
                    │  not_started  │  （新设备，本地无记录）
                    └──────┬───────┘
                           │
                 ┌─────────┴─────────┐
                 ▼                   ▼
          ┌─────────────┐    ┌───────────┐
          │ in_progress  │    │  skipped   │  （用户点击 X/跳过文本/返回键）
          │ current_step │    └───────────┘
          └──────┬──────┘          ▲
                 │                 │
                 │    （24小时超时自动转为 skipped）
                 │                 │
                 ├─────────────────┘
                 │
                 │  （逐步完成 step_1 → step_5）
                 │
                 │  ※ 新设备打开 APP 后自动进入引导，
                 │    用户在 step_1 过程中完成登录后，
                 │    本地状态同步至后端（关联 device_id + user_id）
                 │
                 ▼
          ┌─────────────┐
          │  completed   │  （全部完成）
          └─────────────┘
```

**状态枚举说明：**

| 状态值 | 含义 | 触发条件 | 存储位置 |
|--------|------|---------|---------|
| `not_started` | 未开始 | 新设备首次打开 APP（本地无记录） | 仅本地（隐含状态，无记录即为此状态） |
| `in_progress` | 进行中 | 新设备打开 APP 后自动进入引导，仅因非主动退出（闪退/杀进程）中断时保持此状态 | 本地；登录后同步至后端 |
| `skipped` | 已跳过 | ① 用户点击「X 关闭」或「跳过引导」文本 ② `in_progress` 超过 24 小时未恢复 | 本地；登录后同步至后端 |
| `completed` | 已完成 | 用户完成全部 5 步引导 | 本地 + 后端 |

**步骤编号枚举：**

| 步骤值 | 对应引导步骤 |
|--------|------------|
| `step_1` | 创建策略（含登录环节、默认策略回测） |
| `step_2` | 保存策略（点击仅保存） |
| `step_3` | 我的策略（了解实盘入口） |
| `step_4` | 查看大神策略 |
| `step_5` | 广场社群互动 |

### 6.2 前端本地存储结构

登录前，引导状态存储在前端本地（LocalStorage / SharedPreferences），数据结构如下：

```json
{
  "device_id": "xxx-xxx-xxx",
  "guide_status": "in_progress",
  "current_step": "step_1",
  "current_sub_step": "1-3",
  "started_at": "2025-04-27T10:00:00Z",
  "last_active_at": "2025-04-27T10:05:00Z",
  "skipped_at": null,
  "completed_at": null,
  "gift_claimed": false,
  "synced_to_server": false
}
```

| 字段 | 说明 |
|------|------|
| device_id | 设备唯一标识 |
| guide_status | 引导状态 |
| current_step | 当前主步骤 |
| current_sub_step | 当前子步骤（用于第一步和第三步的精确恢复） |
| started_at | 引导开始时间 |
| last_active_at | 最后活跃时间（用于 24 小时超时判断） |
| skipped_at | 跳过时间 |
| completed_at | 完成时间 |
| gift_claimed | 礼包是否已领取（基于 device_id） |
| synced_to_server | 是否已同步至后端（登录后置为 true） |

### 6.3 接口设计

#### 接口1：同步引导状态至后端

用户在引导过程中完成登录后，前端调用此接口将本地引导状态同步至后端。

| 项目 | 说明 |
|------|------|
| 接口路径 | `POST /api/guide/sync` |
| 调用时机 | 用户登录/注册成功后立即调用 |
| 前置条件 | 需要登录态（Token） |

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| device_id | string | 是 | 设备唯一标识 |
| guide_status | string | 是 | 当前引导状态：`in_progress` / `skipped` / `completed` |
| current_step | string | 否 | 当前步骤：`step_1` ~ `step_5`（`in_progress` 时必传） |
| started_at | datetime | 否 | 引导开始时间 |
| skipped_at | datetime | 否 | 跳过时间 |

**后端处理：**

| 场景 | 处理方式 |
|------|---------|
| 该 device_id 在后端无记录 | 新建记录，关联 device_id + user_id |
| 该 device_id 在后端已有记录 | 以前端传入的状态为准，更新后端记录 |
| 该 device_id 已关联其他 user_id | 不更新关联关系，仅更新引导状态（同一设备可能换账号登录） |

**响应字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| success | boolean | 同步是否成功 |
| guide_status | string | 后端记录的引导状态 |
| current_step | string / null | 后端记录的当前步骤 |

---

#### 接口2：上报引导步骤

前端在用户完成每一步、跳过时调用此接口（仅登录后可调用）。

| 项目 | 说明 |
|------|------|
| 接口路径 | `POST /api/guide/report` |
| 调用时机 | 每步完成时、用户跳过时（仅登录后） |
| 前置条件 | 需要登录态（Token） |

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| device_id | string | 是 | 设备唯一标识 |
| action | string | 是 | 操作类型：`step_complete` / `skip` |
| step | string | 否 | 步骤编号：`step_1` ~ `step_5` |

> 注：`start` action 不再需要，因为引导开始时用户尚未登录，开始状态通过 sync 接口同步。

**各 action 的后端处理：**

| action 值 | 后端处理 |
|-----------|---------|
| `step_complete` | 更新 current_step 为下一步；若 step = `step_5`，则 guide_status 更新为 `completed`，记录 `completed_at` |
| `skip` | 将 guide_status 更新为 `skipped`，记录 `skipped_at`。若携带 step 字段，记录跳过时所在步骤 |

**响应字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| success | boolean | 操作是否成功 |

### 8.4 埋点验证要点（供测试参考）

| 验证项 | 验证方法 |
|--------|---------|
| 登录前事件仅携带 device_id | 在未登录状态下触发的事件（guide_start、guide_skip 等），user_id 应为空 |
| 登录后事件同时携带 device_id 和 user_id | 登录成功后触发的事件，两个字段均应有值 |
| 每步进入和完成事件成对出现 | 完成一步后，日志中应有对应的 `guide_step_enter` 和 `guide_stepN_complete` |
| 跳过事件携带正确步骤 | 在第3步关闭引导时，`guide_skip` 的 `skip_step` 应为 `step_3` |
| 跳过后不再触发引导事件 | 跳过引导后重新打开 APP，不应产生引导相关事件 |
| 登录环节事件完整 | 触发登录 → 登录成功/放弃登录，事件应成对出现 |
| 24小时超时后不再触发引导 | 中断超过24小时后重新打开 APP，不应产生引导相关事件 |
| X 关闭和跳过文本的 skip_reason 不同 | X 关闭为 `close_button`，跳过文本为 `skip_text` |

## 九、补充说明

### 9.1 边界情况处理

| 边界场景 | 处理方案 |
|---------|---------|
| 用户卸载重装 APP，device_id 不变 | 本地记录丢失，但如果用户登录后，后端仍有该 device_id 的记录，可恢复状态。未登录时视为新设备（本地无记录） |
| 用户卸载重装 APP，device_id 变化 | 视为新设备，重新触发引导流程 |
| 用户在引导过程中 APP 版本升级 | 本地引导状态不受影响，继续从中断步骤恢复（24小时内） |
| 用户在引导过程中切换账号 | 引导状态绑定 device_id 而非 user_id，切换账号不影响引导进度 |
| 用户在引导过程中网络断开 | 登录前：引导交互可继续（纯前端展示）；登录环节：需网络，无网络时提示用户 |
| 用户在登录页停留很久再完成登录 | 登录成功后正常继续引导，同步状态至后端 |
| 用户在登录页多次切换登录/注册 | 不影响引导流程，最终登录成功后继续引导 |
| 新手礼包活动到期或下线 | 引导流程不受影响，仅隐藏礼包弹窗和领取入口，引导完成状态正常记录 |
| 引导流程中涉及的功能页面改版 | 引导浮层的高亮定位需跟随页面元素调整，建议高亮定位使用元素ID而非坐标 |
| 默认策略回测耗时较长 | 前端展示加载状态（loading），等待回测结果返回后再进入下一步 |
| 默认策略配置缺失或异常 | 前端展示错误提示，引导流程暂停，不影响用户正常使用 APP |
| 同一 device_id 不同用户登录 | 引导状态跟随 device_id，不跟随 user_id。同一设备只引导一次，防薅羊毛 |

### 9.2 后续扩展性说明

| 扩展方向 | 说明 |
|---------|------|
| 新增引导步骤 | 在 `step` 枚举中新增步骤值（如 `step_6`），前端新增对应浮层，后端步骤流转逻辑相应调整 |
| 引导内容可配置化 | 后续可将每步的引导文案、高亮元素ID、跳转页面等做成后台可配置，运营可自助调整引导内容 |
| A/B 测试 | 可基于 device_id 分组展示不同的引导流程或文案，对比不同方案的完成率和转化率 |
| 引导步骤可选化 | 当前为固定5步顺序引导，后续可支持根据用户画像动态调整引导路径 |
| 多语言支持 | 引导文案抽离为配置项后，可扩展多语言版本 |
| 新手礼包上线 | 待礼包内容确定后，开启礼包弹窗逻辑，前端和后端接口已预留 |

### 9.3 风险与依赖

| 风险/依赖项 | 影响 | 应对方案 |
|------------|------|---------|
| device_id 稳定性 | 若 device_id 在卸载重装后变化，老用户可能被误判为新设备 | 评估当前 device_id 生成方式的稳定性；可接受一定误判率（重新引导不会造成负面体验） |
| 登录流程跳转适配 | 引导过程中登录成功后需跳转至策略编辑页（而非原页面），需修改现有登录成功后的跳转逻辑 | 前端在触发登录时传入来源标识（如 `from=guide`），登录成功后根据来源决定跳转目标 |
| 默认策略需后端预配置 | 第一步引导依赖默认策略数据 | 后端需提前配置好默认策略模板，并提供查询接口 |
| 新手礼包内容待运营确认 | 礼包弹窗暂不上线 | 当前仅预留前端入口和后端接口，待内容确定后再开发 |
| 引导浮层需适配不同机型屏幕 | 小屏设备可能出现气泡遮挡或溢出 | 前端需做响应式适配，气泡位置自动调整 |
| IP 形象（小牛）素材需设计提供 | 前端开发依赖设计资源 | 设计需提前输出小牛的各表情状态切图（指引、庆祝） |
| 回测接口响应时间 | 第一步回测等待时间可能较长，影响用户体验 | 前端展示 loading 动画，必要时后端优化默认策略的回测性能 |
| 本地存储可靠性 | 用户清除 APP 缓存可能导致本地引导状态丢失 | 登录后状态已同步至后端，可通过后端恢复；未登录时丢失则视为新设备重新引导 |
