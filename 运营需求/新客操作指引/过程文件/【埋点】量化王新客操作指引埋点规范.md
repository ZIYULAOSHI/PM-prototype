## 一、概述

本文档基于【PRD】量化王新客操作指引需求，按照量化王现有埋点规范格式，定义新手引导流程所需的埋点事件与属性。

**复用已有事件：** AppViewScreen、AppClick、AppLogin、PolicyCreate 等已有事件在引导流程中正常触发，无需重复定义。其中 AppLogin 事件的 `entry_page` 上报为 `新手引导`，用于区分引导流程中发起的登录。

---

## 二、新增预置属性

| 字段 | 字段含义 | 数据类型 | 是否为空 | 说明 |
|------|---------|---------|---------|------|
| guide_step | 引导步骤 | STRING | 是 | 枚举值：`step_1` ~ `step_5` |
| guide_sub_step | 引导子步骤 | STRING | 是 | 枚举值：`1-1` ~ `1-5`、`3-1`、`3-2`，仅第一步和第三步有子步骤，其余为空 |
| skip_reason | 跳过方式 | STRING | 是 | 枚举值：`close_button`（X关闭）/ `skip_text`（跳过引导文本）/ `back_button`（Android返回键）/ `swipe_back`（iOS侧滑） |

## 三、新增事件

### 23、Guide（新手引导）

| 属性字段 | 字段含义 | 数据类型 | 说明 | 触发时机 |
|---------|---------|---------|------|---------|
| event_name | 事件名称 | STRING | 值 `Guide` | 新手引导流程中的关键节点触发 |
| event_type | 事件类型 | STRING | 枚举值见下方事件类型表 | |
| guide_step | 引导步骤 | STRING | `step_1` ~ `step_5`，无关联步骤时为空 | |
| guide_sub_step | 引导子步骤 | STRING | `1-1` ~ `1-5`、`3-1`、`3-2`，无子步骤时为空 | |
| skip_reason | 跳过方式 | STRING | 仅 `guide_skip` 时上报 | |
| is_login_id | 是否已登录 | BOOL | 仅 `guide_skip` 时上报，标识跳过时是否已登录 | |
| is_new_register | 是否新注册 | BOOL | 仅 `guide_login_success` 时上报，区分登录和注册 | |
| login_method | 登录方式 | STRING | 仅 `guide_login_success` 时上报，一键登录/验证码登录 | |
| screen_name | 页面名称 | STRING | 当前所在页面，取值见下方页面映射表 | |
| title | 页面标题 | STRING | 当前页面标题 | |
| time | 时间 | DATETIME | 事件触发的时间 | |

**event_type 枚举及触发说明：**

| event_type | 含义 | 触发时机 | 关联 guide_step |
|-----------|------|---------|----------------|
| `guide_step_enter` | 步骤进入 | 每个引导步骤的蒙版浮层展示时（step_1 进入即为引导开始，step_5 的下一步操作即为引导完成） | `step_1` ~ `step_5` |
| `guide_skip` | 跳过引导 | 用户点击X关闭/跳过文本/返回键/侧滑时 | 跳过时所在步骤 |
| `guide_login_trigger` | 触发登录 | 用户点击「股票择时」触发登录校验时 | `step_1` |
| `guide_login_success` | 登录成功 | 引导过程中完成登录/注册时 | `step_1` |
| `guide_login_abandon` | 放弃登录 | 用户从登录页返回未完成登录时 | `step_1` |
| `guide_complete` | 全部完成 | 用户在第五步点击「开启你的量化之旅」时 | `step_5` |
| `gift_claim` | 礼包领取（预留） | 用户点击「领取礼包」时（暂不上线） | — |

> **说明：** 不单独设置每步的 complete 事件。step_N 的完成可通过 step_N+1 的 `guide_step_enter` 推导（如收到 step_2 的 enter，即代表 step_1 已完成）。最后一步（step_5）的完成通过 `guide_complete` 标识。

## 四、埋点验证要点

| 验证项 | 预期结果 |
|--------|---------|
| 登录前事件 user_id 为空 | `guide_step_enter`(step_1)、`guide_skip`(登录前)、`guide_login_trigger` 的 user_id 应为空 |
| 登录后事件同时携带 device_id 和 user_id | 登录成功后的所有 Guide 事件两个字段均有值 |
| 步骤连续性 | step_N+1 的 `guide_step_enter` 出现即代表 step_N 已完成，日志中步骤应连续递增 |
| 跳过事件字段完整 | 在第3步点X关闭：guide_step=`step_3`，skip_reason=`close_button` |
| 跳过后不再触发引导事件 | 跳过引导后重新打开APP，不应产生 Guide 事件 |
| 登录事件成对出现 | `guide_login_trigger` 后必有 `guide_login_success` 或 `guide_login_abandon` |
| AppLogin 的 entry_page 正确 | 引导中登录时，AppLogin 的 entry_page 应为 `新手引导` |
| 24小时超时后不再触发 | 中断超过24小时后重新打开APP，不应产生 Guide 事件 |
